# ATS-2 bounded research action loop

**Status: QUALIFIED (2026-10-16) for ATS2_SYNTHETIC_ONLY; ATS-3 dependency gate READY.** This is a thin wrapper over the current `RunPermitV1`, `AttemptLedger`, and native backtest adapter. It adds no scheduler or competing run registry. It does not expose protected-history reads, deployment controls, broker credentials, or orders.

## Supported action

`src.research_control.ats2` currently supports only `development_native_bracket`. `prepare_action` runs the existing strict permit preflight and returns a frozen `ActionContractV1`. Its write scope is `run_log/ats2/accepted/<session>/<trial>`; its input scope is the frozen development inputs named by the permit. The caller must supply the exact reference `run_permit:<permit_sha256>`. Preparation writes no files and launches no process.

`start_action` re-runs preflight, compares the complete permit identity, validates a signed synthetic grant atomically under the `AttemptLedger` admission lock, and reserves the deterministic action identity. Only the native `execute_permitted_native` adapter runs, inside a Bubblewrap-isolated child process with no network, no host home, no issuer key, no trust policy, and no ledger/accepted-output access. There is no shell field, retry count, or caller boolean that grants protected access. A concurrent or repeated start receives the existing attempt decision; a completed action is not silently rerun. Budget exhaustion and other terminal outcomes are final under `NO_AUTOMATIC_RETRY`: a second `start_action` with the same consumed grant is blocked with `TERMINAL_ATTEMPT_RETAINED` and records no new admission.

`observe_run` reconstructs the latest attempt revision and output paths from the original attempt records and filesystem. `OUTPUT_READY` reflects a completed record plus visible output. `verify_result` independently reconciles saved native Parquet files (fills, trades, equity, portfolio state, daily PnL, metrics) against the raw input bars and action parameters using fixed bracket arithmetic, without trusting the worker manifest status, audit evidence hash, or checkpoint checksums, then writes a verifier attestation with source, method, assertions, tolerances, and limitations. This local attestation is cooperative evidence; the same filesystem owner can alter local files.

## Recovery and authority

Attempt events are exclusive-created, newline terminated, flushed and fsynced before the attempt directory is fsynced. Invalid/truncated JSON causes ledger reading to fail. Attempt revisions preserve action metadata and monotonically increasing fencing tokens. Attempts retain their failure/abort events. A missing or uncertain worker observation does not authorize an immediate duplicate. The existing recovery protocol requires an expired lease and its applicable worker/checkpoint evidence before creating a successor replay. The public `start_action` path now writes an initial durable zero-progress checkpoint after entering RUNNING, allowing a real SIGKILLed native launcher to be reclaimed after an expired three-second admission lease, with the same signed grant, identical action/permit identities, original FAILED/ABORTED history and a strictly advanced fencing token. `tests/test_ats2_native_recovery.py` kills the public API launcher, verifies no premature restart, replays the native worker under the original grant, and compares the raw outputs with a separately executed clean control. This is development-only and does not authorize an automatic retry after a terminal FAILED outcome. Fenced publication rejects late writes from old owners and preserves rejected late bytes with attribution.

`start_action` now **requires Linux cgroup v2 and a working systemd user manager**, with no sampled-RSS fallback. It launches the existing fixed Bubblewrap-isolated native worker inside a unique `systemd-run --user --scope` unit. The kernel enforces `memory.max = action.max_memory_mb * 2^20`, `memory.swap.max = 0`, and `pids.max = 128` for the worker and its descendants. The supervisor reads the *actual live cgroup files* and systemd properties (not just launch arguments), tracks `memory.events`, enforces the wall deadline and observed aggregate CPU usage, and requires a verified live memory scope plus clean process exit before accepting outputs. The child also retains `RLIMIT_CPU` and the 64 MiB individual-file limit. A transient OOM results in `BUDGET_EXHAUSTED`; a missing controller, incorrectly configured limit, unknown scope visibility, or unverifiable termination fails closed without accepted output. The signed action's memory budget is never silently enlarged.

The precise trust boundary is a kernel cgroup operated by the systemd *user* manager. A normal completed transient scope may be collected before the final query; `COLLECTED` means **only** that systemd no longer knows the unit. It is acceptable for a positive run exclusively alongside an earlier observation of the correctly configured *live* kernel cgroup, a clean launcher exit, no observed OOM, and a hashed immutable resource report. It never suffices by itself. The resource report is written under `run_log/ats2/resources/<attempt>.json`, bound into the final checkpoint, and checked again by `verify_result` before a numerical attestation can become `VERIFIED`. Reported memory peaks are observations, not a complete sampling guarantee; the kernel's `memory.max` and swap limit are the actual enforcement mechanism. Same-UID host owners can still change systemd properties or tamper with local files, so this does not promise owner-resistant confinement. It constrains the scoped process tree, not every other process of the user or host.

The 2026-10-16 qualification used an authentic signed synthetic development action. Under **512 MiB**, native execution and numerical verification passed with actual `memory.max=536870912` and `memory.swap.max=0`. A distinct **128 MiB** signed action triggered the kernel OOM killer with `memory.max=134217728`, `Result=oom-kill`, and preserved `FAILED` evidence; retry with its consumed grant was denied. The prior 32-task experiment hung because the native worker reached `TasksCurrent=32`; the task limit was increased to 128 **without changing the signed memory budget**. Earlier failed runs were retained. Native launcher crash recovery now refuses a successor while the original scope is active or its state is unknown. There is no automatic retry. The worker lock includes PID, process start ticks and UID to avoid treating PID reuse as the same owner.

The output directory is attempt-specific. Checkpoints hash visible files, and `verify_result` independently reconciles raw native data before publishing an immutable verifier record through a current fencing token. A local fence protects cooperative writers using `AttemptLedger.publish_fenced`; it is not owner-proof storage security. The native adapter writes its trial artifacts before the final checkpoint, so interrupted partial output remains evidence and is never silently accepted as complete. Atomic staged publication uses `O_EXCL` plus fsync; crash evidence is preserved and never silently accepted as complete.

## Synthetic and production authorization

The existing `RunPermitV1` grants only a bounded native research run with `live_order_authority=false`. A preflight or stage receipt never grants protected access. ATS-2 now demonstrates positive protected **synthetic fixture** authorization through the same typed Ed25519 grant validator, with exact operation/effect binding (`synthetic_protected_fixture_read`, `protected_data=true`, `trading=false`). The fixture is created exclusively from a fixed synthetic magic header plus freshly generated random bytes. A separate external test issuer signs the immutable source, data, spec, config, window and selection scope. The worker receives only the one fixed synthetic input and a digest-only output mount under Bubblewrap. Its host issuer key, trust policy, accepted evidence and network are inaccessible. The one-use claim is inserted under an OS file lock with `O_EXCL` and fsync before the fixture is mounted. Replayed grants, fake stage receipts, forged signatures, missing issuers, revoked and expired grants, mutated windows/selections, and altered identities fail closed. This fixture-only proof is not a general protected-data API: ordinary `start_action` still denies protected scopes. There is **no trusted production issuer** for actual protected history or deployment and no broker authority. Those paths remain closed and unqualified. `start_action` requires a signed Ed25519 synthetic grant validated under the `AttemptLedger` admission lock against durable admission records. The verifier accepts only the exact signed action, data/source/config/spec identities, window and selection hash; its rejection corpus covers expiry, revocation, replay, forged signature, unknown issuer, wrong action/scope, changed identity and a stage receipt standing in for a grant. A Linux Landlock sandbox denies the child access to the fixture's issuer private key while permitting its allowlisted policy and synthetic workspace. Bubblewrap namespace isolation is proven functional on this host; the nested Codex sandbox cannot create namespaces, which is not a host infrastructure blocker. Synthetic authorization-boundary experiments qualify only the tested fixture, key separation and Landlock behavior. They do not qualify production permissions.

## Independent verification

`scripts/ats2_outside_judge.py` is an independent outside-judge replay that does not import ATS verification or execution code. It parses frozen attempt files and checks native Parquet evidence against the action, frozen inputs, and an independently coded bracket/accounting model. It validates recovered multi-attempt histories: valid FAILED/ABORTED ancestors are retained, strictly monotonic fencing tokens are required, and exact `parent_attempt_id` successor linkage is enforced. It rejects substituted permits, impossible cash/equity, missing native files, tampered fills, contradictory attempt identity, and contradictory transition history.

Supervisor regression probes (retained evidence under `run_log/ats2/`):
- `.workspace/ats2_budget_replay_probe.py` — consumed grant cannot obtain second admission after terminal budget exhaustion
- `.workspace/ats2_saved_numeric_probe.py` — incorrect saved fill prices with consistent checksums are rejected by raw numerical audit
- `.workspace/ats2_admission_security_probe.py` — 10/10 negative authorization cases through actual `start_action`
- `.workspace/ats2_missing_grant_probe.py` — no grant means `TRUST_POLICY_MISSING` and zero admissions
